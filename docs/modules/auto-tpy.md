# Buffered Auto TPY

[Documentation index](../README.md) · [Project README](../../README.md)

Feature of [Chat Tools](chat-tools.md); it is not a separate module.


In **Chat Tools → Overview → Auto TPY**, configure your whitelist before enabling automatic acceptance. The feature is off by default. Edit **Chat Tools → Auto TPY** module settings to adjust the send interval, buffer size, reply timeout, retry backoff, attempt limit and in-flight window.

- **Sending:** fixed interval defaults to **500 ms**; zero means at most one command per client tick. Incoming requests keep buffering while sending is paused or replies are outstanding. The buffer defaults to **1,024** requests (maximum **16,384**); overflow rejects new players visibly and retains existing entries. Duplicate-suppression history is bounded at 32,768 tracked players; if that fills, new admissions pause until protected records expire rather than forgetting cancellations.
- **Priority:** due retries first, then Meteor friends within each group, then arrival order. A retry waiting for backoff does not hold up other eligible requests. Strict priority may delay ordinary requests under sustained load.
- **Trust:** whitelist-only defaults on. **Allow Meteor friends** optionally admits friends without whitelist membership. The **blocklist overrides both** and is checked again before every send. Requests to teleport players to you default on; requests to move you to them default off.
- **CSV:** the Auto TPY page imports or accepts dropped `.csv`/`.txt` username files into the whitelist. Imports append, trim names and deduplicate ignoring case; the summary reports invalid names and blocked overlaps. A recognised Username/IGN/Name column is selected; without a header, multiple rows use the first column. Comma, semicolon, tab, quoted single-line cells, UTF-8 and BOM UTF-16 are supported. Multiline quoted cells and unmatched quotes are rejected. Each file is limited to **1 MiB**; a failed batch leaves the list unchanged. Files are read off the game thread. Clan imports remain separate.
- **Retries:** sending a command is not success. Unconfirmed attempts retry after **3 seconds** plus backoff, with **3 total attempts** by default. Initial backoff is **1 second**, doubles on each retry, and caps at **30 seconds**. Cancelled, expired, manually answered or newly blocked requests stop retrying. Unknown replies stay unconfirmed; after overlapping attempts, timeouts or manual intervention, generic confirmations remain ambiguous for that session and named confirmations are required. Narrow server-reply recognition may need adjustment after live server testing.
- **Adaptive timing:** optional, defaults off, starts at your fixed interval with default bounds **50–5,000 ms**. Ten distinct attributable confirmations reduce the interval by 10%; attributable rate limits slow it down. Ambiguous rate limits pause sending without training. Explicit server waits override both fixed/adaptive pacing and may exceed the maximum. Timeouts alone never teach the system a faster or slower rate.
- **Controls:** view queued/awaiting/retry counts, overflow and the latest result; cancel individual entries, clear the queue or reset learned timing. Queues and learned speed reset on disconnect, transfer, account change or disable. Lists and configuration remain saved. Identical prompts for a recently completed/cancelled request are suppressed until its original expiry and a 120-second duplicate window have elapsed; a fresh identical invitation during that window may need manual acceptance.

Buffering absorbs bursts; it cannot prevent request expiry when sustained incoming traffic exceeds the server's permitted sending rate. Adaptive feedback uses conservative synthetic-tested wording; actual server confirmation and rate-limit messages require live validation.
