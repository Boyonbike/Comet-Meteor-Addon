# Chat Tools

[Documentation index](../README.md) · [Project README](../../README.md)

Module: **chat-tools**. Open **Meteor → Comet → chat-tools**.

Enable **chat-tools** and press **Y** during gameplay, or click **Open Chat Tools** in the module settings. Change the shortcut under **Messages → open-popup-key**. Chat Tools is one movable, resizable window with the same layout at every size: a left sidebar listing the pages, a header with the page title, a short description, the **Waiting for you** bell and the close button, a scrolling page body, and a footer with the message bar. Narrow windows shrink the sidebar to icons, with badges turning into dots. Every page, settings category, player action and private conversation changes the body in place. Drag the header to move the window and the bottom-right corner to resize it. Like normal chat, the window is exempt from Meteor's **GUI Move**: typing never walks you around, and movement keys held when it opens are released. Normal chat has no extra HUD strip; clicking an online player's name opens their conversation inside this same window and preserves your normal-chat draft.

Every page is built from the same parts, so the window reads as one system: an optional toolbar row, section captions (with a count or a link such as **Manage** on the right), grouped lists whose rows join into one card, shortcut tiles, switches, steppers and one set of buttons — accent **primary** actions, outlined **secondary** actions, quiet **ghost** actions and red **danger** actions. Text uses the bundled Inter typeface and icons come from the bundled Lucide set; both are smooth vector fonts, and shapes are drawn in real screen pixels with anti-aliased corners, so nothing looks blocky at any GUI scale. The window chooses its own size from your screen height instead of following Minecraft's GUI scale; set **General → window-scale** above zero to pick a size yourself. Meteor's accent colour marks the selected page and primary actions. Action results appear briefly as a notice above the footer instead of moving the page.

The sidebar lists **Overview**, **Players**, **Clan**, **Homes**, **Hotspot**, **Auto TPY** and **Settings**. Players carries an unread-message badge, Auto TPY a count of buffered requests while it is on, and Clan a dot showing the Discord sync state (green after a successful sync, amber after a failed one, accent while a sync runs). **Overview** starts with a player search, **Hotspot** (sends `/hotspot`, shown when the server offers it) and **Reply**. Below them, **Waiting for you** lists everything that needs you — incoming teleport requests with **Accept** and **Decline**, conversations with unread messages with **Open**, and a failed Discord sync with **Fix** — and disappears once nothing is waiting. Then come any active home/TP countdowns, status tiles for Auto TPY and the clan sync, favourite homes as shortcut tiles that wrap into extra rows, and recent players. Each tile teleports to its home with one click; **Manage** opens Homes and **View all** opens Players. Typing in the search narrows the recent list to matching players; Enter opens Players with the name filled in. **Reply** opens the last incoming DM's conversation when known, otherwise asks for the reply in a dialog and sends `/r` (or `/reply`). Each active countdown shows its own **Cancel** button only while the server still allows that teleport or request to be cancelled.

**Players** has a search bar followed by **Recent** and **Meteor friends**. Both player search bars filter immediately by the start of a name, ignoring case: typing `s` shows `Sam` and `Steve`, but not `Oscar`. Matches include recent contacts, Meteor friends, online players and incoming TP requests; Players shows additional online matches below the friends. Clearing the search restores the regular lists. Recents follow interaction order from messages and TP requests; partial searches do not create recent contacts. Up to 100 recents are saved per server/account in the hidden **recent-players** setting, so they return after rejoining or restarting the game. Friends come directly from Meteor's Friends list. Overview and Players rows share one layout: an initial avatar with an online dot, the player name with an unread badge, online/friend status (or an outgoing request/warmup/cooldown countdown), and **Message**, **TP** and **⋯** actions. **TP** sends `/tpa <player>`. An incoming request adds a second line to that player's row with its expiry countdown, **Accept** and **Decline**. **⋯** fills Players search with that name and lists Meteor friendship and configurable player commands below the lists; a command that needs more text, such as `/msg <player> `, asks for it in a dialog.

**Clan** lists the members maintained by [Discord IGN Sync](discord-ign-sync.md). Meteor friends stay first (online ones on top, then A–Z). Everyone else appears in **Members by role**, ordered by their highest Discord role, then A–Z; members without assigned roles appear last. Every account shows its owner's Discord username beside its IGN, followed by all assigned Discord roles in hierarchy order, for example `Alice (@discord_owner) · Officer · Member`. All of a member's comma- or slash-separated alts show the same Discord owner. The default `@everyone` role is omitted, and accounts with no assigned roles show **No role**. Long role lists wrap so all roles remain readable. Role metadata persists across restarts and refreshes on successful syncs. Rows retain Message, TP and player actions, plus an **×** to remove an entry locally; a subsequent Discord sync may add it back. The Clan CSV picker, dropped-file import, search-to-add field and manual Add-to-clan player action have been removed. The general Overview/Players search still opens conversations and player actions. The roster persists in the hidden **clan-members** setting, shared by every Minecraft server. It is maintained by Discord sync rather than manual-add controls.

Meteor friends' and clan members' names are coloured in chat and in the tab list, each with its own switch and colour. Friends use **friend-chat-color** and **friend-tab-color** (Meteor's friend green by default), switched by **highlight-friends** and **highlight-friends-tab** in General. Clan members use **clan-chat-color** and **clan-tab-color** (orange by default), switched by **highlight-clan-chat** and **highlight-clan-tab** in the Clan group. All four switches are on by default. The tab list can also highlight their rows with a bar in a separate colour: **highlight-friend-rows** with **friend-row-color**, and **highlight-clan-rows** with **clan-row-color** (both off by default). The bar uses its colour's alpha, so lower the alpha for a fainter bar; the defaults are about 40% opaque. **Settings → Name colours** has every switch, each with a swatch that opens Meteor's colour picker. A clan member who is also a Meteor friend gets the friend colour, unless that friend switch is off; names and rows decide this separately. The Chat Tools window shows names in their chat colours. Name colouring keeps server prefixes and Meteor's **Better Tab** formatting; a tab name that never spells out the username, such as a nickname, is coloured whole.

**Message** changes the window to a conversation. The tabs stay available, and the back arrow returns to the previous view. The conversation header shows the player, their status and **TP** / **Add friend** (or **Unfriend**); an incoming TP request from them appears below it with **Accept** and **Decline**. Incoming and outgoing messages use left/right bubbles, with incoming messages kept unread while you scroll up. Public-chat and per-player drafts are retained independently while switching views. Enter or the send button submits the message bar, whose chip shows where the message goes: plain text sends public chat on ordinary pages or a DM in a conversation, and `/commands` run as server commands. The bar is only for chat — anything else that needs typing opens a dialog. **message-command** defaults to `/msg {player}` and must include `{player}`. Outgoing DMs appear in history after the server echoes them; until then they show as dimmed bubbles. A server's whisper delay, such as 6b6t's `Please wait 2 seconds before sending another whisper!`, no longer loses messages: DMs from a conversation, and `/msg`, `/w`, `/tell`, `/whisper`, `/r` or `/reply` typed in the composer, wait in a queue of up to 20. A refused whisper is sent again as soon as the reported wait is over (up to three tries) and the refusal is hidden; the reported delay then spaces out later whispers so they are not refused at all. Whispers typed in normal chat are sent straight away but count towards the delay, and their refusals still show.

**Send queue.** Enter clears the bar at once so you can keep typing; the message joins a queue that sends at the server's pace. Public chat leaves **chat-cooldown-ms** apart (5 seconds by default) and whispers **whisper-cooldown-ms** apart (2.5 seconds), in separate lanes, and a longer wait the server reports — such as `Please wait 5 seconds before sending another message` — still wins and resends the refused message. While anything is waiting, a tray above the bar lists up to three messages, soonest first, with where each is going, a live countdown and a button to cancel it. Turn **queue-chat** off (Messages) to send public chat straight away. Chat typed in normal chat is not queued but restarts the cooldown.

**Waiting for you.** While teleport requests, unread messages or a Discord sync problem are waiting, the header bell shows a count and opens Overview, and while you play a small notification stays in the top-right corner of the screen until you have dealt with them, naming what is waiting and the key that opens Chat Tools. Turn it off with **Messages → waiting-notification**.

**Homes** has **New home**, **Refresh** and **Server list**, then any active home countdowns and every known home with a favourite star, **Rename** (pencil), **Delete** (bin) and **Go**. A gold star marks a favourite; click a grey star to add one. Favourites appear on Overview, persist through Meteor settings separately for each server/account, and follow confirmed home renames/deletions. **Go** sends `/home <name>` immediately. **Rename** and **New home** open a dialog that asks for the name, checks it (no spaces, not already one of your homes) and shows the command it will send — `/homerename <old> <new>` or `/sethome <name>`. **Delete** asks you to confirm before sending `/delhome <name>`. Creating a home only adds it to the current server's list after a successful reply. Home actions keep the page open, and a home's countdown also replaces its status line.

Homes are discovered from `/home ` tab suggestions, clickable server home commands and common `Homes: ...` lists, plus manual fallback names in the module's **homes** setting. **Refresh** requests suggestions and **Server list** sends `/homes`. Favourite names also remain available as shortcuts after reconnecting. Home controls use standard server home commands and remain visible when the command tree does not advertise them; the server enforces availability and permissions.

**Hotspot** has **Go to hotspot**, **Refresh** and **End hotspot** (which asks you to confirm before sending `/hotspot kill`), a **Details** card and a **Manage** list for creating/cancelling a hotspot and its appearance and notification controls. Opening it requests `/hotspot info` when the server advertises the command. The details card shows recent server replies from that request and hotspot messages; it does not invent coordinates or a destination. Nested hotspot preferences update the same page, and controls that need a value ask for it in a dialog.

The **Clan** page is also where [Discord IGN Sync](discord-ign-sync.md) is run. A status card at the top shows when the last sync succeeded, how many accounts are linked and whether automatic sync is on, with **Sync now** (and **Fix connection** after a failure). **Members** shows the roster; **Discord connection** holds **Discord server ID**, **#ign channel ID** and a masked **Bot token** that stays blank to keep the saved one, with **Save and sync** and **Save connection**, then **Sync automatically**, **Sync every**, **Keep the clan list in step** and **Keep the Auto TPY whitelist in step**.

**Settings** holds every Chat Tools, Auto TPY and Discord IGN Sync setting as native controls — switches, steppers whose value can be clicked to type an exact number, colour swatches that open Meteor's colour picker, key bindings (click **Change**, then press a key; Backspace clears), choice buttons and text values edited in a dialog, with tokens and passwords never shown. List settings open Meteor's own editor. Chips choose **Chat Tools**, **Auto TPY**, **Discord sync**, **Teleport cooldowns** (Auto/Manual lengths) and **Server settings** (grouped server controls for chat, bots, notifications, homes/TPA, appearance, hotspot and gameplay); the search box above them searches every setting at once. Server categories show an arrow; command rows show the command they send, and commands needing a value ask for it in a dialog. Server controls follow the [6b6t command reference](https://www.6b6t.org/en/commands). Unadvertised server settings are hidden after the command tree arrives. Esc closes a dialog, then goes back through a settings category, then to Overview, then closes the window; a conversation first returns to its previous view. Tab switches keyboard focus between the visible fields and the message bar.

Player actions use the current server's Brigadier command tree with **auto-detect**, supplemented by **command-options** entries such as `Label | /command {player}`. `%player%` is also accepted, and a missing placeholder appends the player name. End a template with a space when more text is needed. Complete commands run when chosen; a template that needs more text asks for it in a dialog showing the command it will send. Plugin commands that expose targets as plain text need configured entries.

Incoming TPA answers use the server prompt's own clickable commands, or its advertised `/tpy`, `/tpaccept`, `/tpyes` (and `/tpn`, `/tpdeny`, `/tpno`), falling back to `/tpy` and `/tpn`. The default unreported request expiry is **tpa-request-timeout** (120 seconds). Home and TP timers use server-reported durations, including commands typed outside the window. Unknown warmup durations say **Waiting for server** (**awaiting server** in the HUD); reaching zero still waits for a completion/cancellation reply. After confirmed success, the countdown switches to a Home or TP **cooldown** and keeps the destination/player name. Success means a completion line (such as `Teleported to destination!`, or 6b6t's `Teleporting to: <home>`), or the network moving you to another of its servers as the warmup ends — on 6b6t, teleports to a player or home on another worker finish that way. Wait times such as `You have to wait 9m 35s to teleport again.` are read whole, and a generic wait like that belongs to the command you just retried, because 6b6t keeps separate home and TPA cooldowns. Times of a minute or more read as `9m 35s`. Explicit server times take priority, including cooldowns announced alongside a warmup or reported after a retry. The module can calibrate future cooldown estimates from a known success followed by a server-reported remaining time. Cancel TP uses `/tpacancel` or the advertised `/tpcancel` alias. Cooldowns, completed actions and elapsed warmups cannot be cancelled.

**Settings → Teleport cooldowns** sets how long Home and TP cooldowns last for the current account on the current server; ranks, rewards and other reductions differ per player, so each server/account keeps its own values. After a confirmed teleport the countdown uses, in order: a time the server states (exact, no `~`), your **Manual** length, the length **learned** from the server, then the fallback. **Auto** follows what the server reports: whenever you retry during a cooldown and get a reply such as `You have to wait 4m 10s to teleport again.`, the countdown switches to that exact time and the full length (remaining time plus time since the teleport) is learned for that command. **Manual** pins your own length, for example right after claiming a reward; learning continues underneath, and the row shows the learned value. The minus/plus buttons step by 5 seconds under a minute, 30 seconds under ten minutes, then a minute; pressing them while on Auto switches to Manual from the current value, and **0 / Off** means no cooldown. Changing a length re-times an estimated countdown that is already running from when its teleport finished. The global fallbacks (**30 seconds** each by default, **0** disables) are **home-cooldown-seconds** and **tp-cooldown-seconds** in the module's **Teleport Cooldowns** group, used until the server has reported a cooldown. Estimates show `~`, for example `Home base: cooldown ~30s`; server-reported cooldowns omit it. Failed/cancelled teleports and unconfirmed warmups never start estimated cooldowns. Retries/cancel commands and duplicate success messages do not erase or restart an active cooldown. Learned and manual lengths are stored in the hidden **saved-cooldowns** setting.

A separate Meteor HUD element, **Comet → tp-home-countdown**, shows the same live home/TP warmups, post-teleport cooldowns and incoming request expiry while playing. Add it from Meteor's HUD editor to move, scale and colour it like the other Comet HUD elements. It hides when idle or Chat Tools is disabled, and shows sample countdowns in the editor.

DM recognition supports common `From Name:`, `To Name:`, `Name whispers [to you]:`, `You whisper to Name:` and `[Name -> me]` / `[me -> Name]` formats, including the player-head sprite servers such as 6b6t put before the name (`You whisper to [unknown player head] Name:`). Add full-line regexes under **incoming-dm-patterns** and **outgoing-dm-patterns**, with username in capture group 1 and body in group 2; invalid entries are ignored. **hide-private-messages** defaults off, and **dm-toasts** defaults on. Opening a conversation marks it read; scrolling up keeps new arrivals unread until you return to the bottom. Name colours preserve normal chat formatting and click/hover actions while colouring whole friend and clan member names. Recognised DMs and player-authored chat cannot imitate server home/TP results.

Conversations (up to 100, with 250 messages each), queued whispers, drafts and frame position remain in memory for the current connection and clear on disconnect/server change or module disable. Moving between servers of one network, such as 6b6t's workers, keeps them along with homes, requests and timers. Recents and favourites persist per server/account.

## Buffered automatic acceptance

See [Buffered Auto TPY](auto-tpy.md) for its Discord role filter, whitelist, CSV import, blocklist, buffering, retries and optional adaptive timing.

On the **Auto TPY** page, dropped CSV/TXT files target its independent whitelist. Other pages do not import dropped files. Switch from Blocklist to Whitelist before dropping a file there. See [Buffered Auto TPY](auto-tpy.md).
